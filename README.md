# GenAPI <!-- omit in toc -->

Not to be confused with "GenAI", Gen**API** generates an OpenAPI schema and validation functions from your TypeScript code.

### Overview

This is distinct from (most) other generation tools in that it uses a type-first approach, with schema objects being generated from TypeScript types:

<tr>
<td><a href="https://zod.dev/basics#inferring-types">Zod</a></td>
<td>GenAPI</td>
</tr>
<tr>
<td>

```ts
const Player = z.object({
    username: z.string(),
    xp: z.number()
});

type Player = z.infer<typeof Player>;
```

</td>
<td>

```ts
// only the type definition is needed
interface Player {
    username: string;

    xp: string;
}
```

</td>
</tr>

Neither of these approaches are objectively better than the other, however I prefer the former since it means documentation for types can exist in both the static type system and in the generated schema.

You can then use the schema generated by this tool for input validation, and/or write it to an `openapi.json` file.

### How it Works

Generation is split into 2 stages, **parsing** and **building**.

**Parsing** is done first, the TypeScript AST of your project is read and endpoint-related types such as request bodies, responses, and paths are stored.

**Building** then converts the stored objects into JSON form for the schema file and makes the validation functions.

### Key Features

- "Smart" Generation
  - Uses `$ref` for types with multiple references.
  - Unions with `unknown` and `any` match TypeScript union behaviour.
- Highly Configurable
  - You tell the generator how to find and read the relevant types.
- Deterministic
  - You can commit a generated schema file to VCS.
  - Things like object keys appear in the order they are written in the code.
- Built-in Validation
  - Use JSDoc tags to attach validation logic to types (which themselves are validated).

### Limitations

Non-URL JSDoc links are not converted to references, instead they're just shown in bold:

```ts
type SomeType = // ...

/** Some description, {@link SomeType} */
type SomeOtherType = // ...
// outputs **SomeType**, not #/components/schemas/SomeType
```

Circular references can only be displayed in the schema, attempts to generate validation functions for types with circular references will error:

```ts
// fine for response bodies (since those are never validated), but not for anything else
interface MyInterface {
    someKey: MyInterface;
}
```

You need to have at least a basic understand of the TypeScript compiler (namely AST traversal) in order to configure the generator.

### Requirements

The only dependency you need is TypeScript. The generator itself was written on [Bun](https://bun.com/get), but any JavaScript engine should work just fine.
